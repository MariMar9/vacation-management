## Shared Test Profile

- Use one synthetic department, `DEPT-TEST-001`, with directly assigned synthetic projects `PRJ-TEST-*`; no multi-level organizational hierarchy is modeled.
- Use synthetic employee identifiers `EMP-TEST-*`. Never import real personal data or call real ServiceNow, Active Directory, email, or Teams endpoints.
- The eventual hosted identity direction is Microsoft Entra ID OIDC. Automated/local tests use a deterministic fake identity provider and seeded authorization records; they do not call Entra.
- Business dates are date-only values interpreted in `Europe/Madrid`. Periods are inclusive calendar dates; no half-days, working-day, or holiday-calendar calculation is included.
- All decisions in this record are test defaults and must be re-approved before use with real users, real organizational data, external integrations, regulated data, or production deployment.

## Feature-Level Decisions

### F-001 Request Lifecycle

- States: `PendingProjectApproval`, `PendingDepartmentApproval`, `Approved`, `Rejected`, `Cancelled`.
- The F-001 request record owns its lifecycle; F-002 decisions cause transitions. Rejection at either approval level is final. No `Taken` state is persisted; it is a derived history label.
- Cancellation is allowed only for the requester while `PendingProjectApproval`, before any project decision. Approved/rejected requests cannot be cancelled in this test scope.
- History covers all retained requests for the requester. Views distinguish pending, approved, and non-approved (`Rejected` or `Cancelled`); “taken” means approved and end date before current business date.
- FR-024 is satisfied by having no alternative-period action.

### F-002 Approval and Delegation

- Project approval is required before department approval; both are required for final approval.
- One decision per level. Duplicate/stale commands return conflict and do not overwrite an existing decision.
- Rejection requires a non-empty 1–500 character reason. Approval reason is optional and capped at 500 characters.
- Read-only assessment is represented by the review query. There is no independent `assess` or `close` mutation.
- Only same-project, time-bounded project delegation is supported as described by Q-009.

### F-003 Demand and Capacity

- Support department and direct-project scopes with explicit date-range filtering; do not infer nested scope.
- Count unique active synthetic members with Approved requests overlapping the inclusive range. Percentage is numerator divided by active members in the selected scope; zero-member scopes return zero counts and a null percentage.
- The 70% marker is a display advisory only. Optional capacity limits are also advisory and never change request acceptance/approval.

### F-004 Notifications and Escalation

- Events and recipients are the Q-018 list. Notification delivery is an outbox/simulator, not SMTP or Teams.
- Reminder at 3 calendar days and one escalation at 5 calendar days from the current pending-level start; suppress both after approval, rejection, or cancellation. No repeats.
- Notification payload contains request ID, event, recipient, decision/status, and a link; do not include reason text or unnecessary employee details.

### F-005 Organizational Data and Integrations

- Simulator snapshot includes department, employees, projects, direct memberships, and explicit approver assignments with stable synthetic IDs and `snapshotVersion`/`generatedAt`.
- Validate all references before atomic publish. On failure, retain the last valid snapshot and expose stale/error status.
- Export only final Approved requests, after both F-002 approvals; use the daily outbox and idempotency/retry policy in Q-017. Do not call external systems.

### F-006 Entry and Access

- “Try the application” means pre-provisioned test users in the isolated synthetic-data environment; no public signup, trial clock, or production trial.
- Requester: create, read own, cancel eligible own requests. ProjectApprover: read assigned project requests, record project decisions, create/revoke same-project delegation. DepartmentApprover: read department requests awaiting department action, record department decisions, view demand, and set advisory capacity limits.
- Users may have more than one role, but self-approval and cross-scope access are denied. Missing identity is 401; authenticated but unauthorized is 403.
